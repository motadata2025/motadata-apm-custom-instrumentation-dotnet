# Contributing to Motadata.Apm.CustomInstrumentation

Thank you for your interest in contributing to the Motadata.Apm.CustomInstrumentation library! As this is a proprietary library, we have specific guidelines for internal and authorized external contributors.

## Getting Started

1.  **Clone the repository**
2.  **Open the solution** in Visual Studio or your preferred IDE.
3.  **Restore packages** to ensure all dependencies are available.

## Development Workflow

1.  **Create a Branch**: Always work on a feature branch, not directly on `main` or `master`.
    *   Format: `feature/your-feature-name` or `fix/bug-description`
2.  **Code Style**: 
    *   We follow standard C# coding conventions.
    *   Ensure all public methods have XML documentation comments.
    *   Keep the code `clean` and `readable`.
3.  **Unit Testing**:
    *   (Coming Soon) Ensure all new features are covered by unit tests.
    *   Run existing tests to ensure no regressions.

## Commit Guidelines

*   Use clear, descriptive commit messages.
*   Reference issue numbers if applicable (e.g., `Fixes #123`).

## Pull Request Process

1.  Update the `CHANGELOG.md` with details of changes to the interface.
2.  Update the `README.md` with details of changes to the interface, this includes new environment variables, exposed ports, useful file locations and container parameters.
3.  You may merge the Pull Request in once you have the sign-off of two other developers, or if you do not have permission to do that, you may request the second reviewer to merge it for you.

## Reporting Issues

If you find a bug or have a feature request, please file an issue in our issue tracker with:
*   Use a clear and descriptive title.
*   Describe the exact steps to reproduce the problem.
*   Describe the behavior you observed after following the steps.
